# 电路模拟器

Gandi/TurboWarp 非沙盒逻辑门扩展。界面语言跟随 Scratch/TurboWarp：英文名称为
扩展英文名为 `circuit simulation`，简体中文名称为 `电路模拟器`，扩展 ID 为
`bsen975-circuit-simulation`。

扩展源码内嵌了 Base64 Data URI 格式的扩展库封面和 NOT 门图标，不依赖外部图片文件；
侧栏使用单独展平的方形 PNG，积木左侧使用 SVG，封面通过 Gandi 扩展库元数据提供。

积木分组、积木文字和操作菜单支持英文与简体中文。“添加元件”的类型菜单始终显示
标准英文类型名，例如 `LEVEL_INPUT`、`NOT`、`HALF_ADDER`、`ADDER8` 和 `REGISTER`，
避免电路数据和文档中出现多套名称。

第一次使用可以点击扩展顶部的“打开使用指南 / Open User Guide”按钮，在编辑器内查看
快速说明；更完整的 NOT 门示例见 [使用指南](./USAGE.md)，全部元件定义见
[元件参考手册](./COMPONENTS.md)。

## 推荐使用顺序

1. 执行“启动电路模拟器”。支持 Worker 的浏览器会创建独立计算线程。
2. 执行“清空当前电路”，初始化一个空电路。
3. 添加 `LEVEL_INPUT`、逻辑门、需要的 `VIA` 过孔和 `LEVEL_OUTPUT`。
4. 按端口名称连接元件。
5. 载入测试用例并选择状态模式，然后运行全部测试；`LEVEL_INPUT` / `LEVEL_OUTPUT` 会自动成为接口。
6. 从“测试结果 JSON”读取结果。
7. 项目结束时执行“关闭电路模拟器”，释放 Worker。

绑定菜单可以选择当前角色、当前克隆体或运行中的其他角色/克隆体；目标删除后，对应元件
和连线会一起移除。“不绑定”表示元件只存在于模拟器中。

### 存储器初始化、绑定和调试

- ROM 载入、RAM 读写/清空和存储器内容 JSON
- 查询角色或克隆体绑定的元件
- 电路结构、运行状态和完整快照由同一个数据积木查询

模拟器没有后台循环，平时不会自行改变状态。“模拟电路 N 步”只会执行 N 步：每步先让
组合逻辑稳定，再让所有 `DELAY` 同时锁存并采样寄存器和 RAM 的 CLK 上升沿。“传播电路
直到稳定”只计算组合逻辑，不推进时序元件；“产生时钟脉冲”会通过指定输入元件制造
`0 -> 1` 上升沿，每个脉冲包含低、高两个完整步骤，因此 DELAY 会推进两次。

传播和验证积木的 Hz 控制主动调用期间的节拍上限，范围为 `0..1000`；`0` 表示不限速。
传播时每次受影响元件求值算一个节拍，验证时每组用例算一个节拍。单组验证使用从 1 开始
的用例编号，结果 JSON 的 `total` 为 1。

正常电路运行确实依靠引脚连线：ROM 通过 `ADDR -> DATA`，RAM 通过
`ADDR/DIN/WE/CLK -> DOUT` 与其他元件连接。直接装载 ROM、读写或清空 RAM 的积木只是
关卡开始前的初始化和开发调试接口，不会替代这些连线。

“当前电路的数据 JSON”有三种结果：结构只保存元件与连线，适合关卡模板；运行状态还会
包含实时端口和网络电平，主要用于调试，但不能直接导入；完整快照可重新导入，并额外保存
DELAY、RAM、ROM、寄存器引脚和上一次 CLK 电平，适合继续一个已经运行到中途的电路。

验证模式默认选择“每组重置”，每个用例开始前会清零引脚、DELAY、寄存器和 RAM，但保留 ROM；
“连续保留状态”会让后一组用例继承前一组的时序状态，适合验证计数器、状态机等连续过程。

可变宽度元件在添加时支持 `1`、`2`、`4`、`8` 位；其数据引脚采用所选宽度，控制引脚
仍可能固定为 1 位。添加后可以再次修改位宽；不兼容连线会自动断开。将“端口的属性”
切换为“位宽”，可以查询任意已添加元件的实际引脚宽度。

`VIA` 是例外：它只有一个无源端口 `IO`，忽略添加积木中的位宽，也不能手动改宽。所有
在同一点交汇的线路都连接 `VIA.IO`；它会从整个网络自动推导 `1/2/4/8` 位，未连接或只连
其他 VIA 时报告 `0` 位。向同一 VIA 网络接入不同位宽会原子报错。没有 VIA 的几何交叉
不会在后端自动合并，交叉坐标仍由前端处理。

每条物理线路都有独立且稳定的 `lineId`。前端创建线路时应填写自己的 ID；留空时后端会
生成 `line-1`、`line-2` 等名称。线路查询返回 `id`、`from`、`to`、`width`、`value` 和
`netId`，可直接用于检查电气状态和关联前端绘图对象。后端不保存坐标、折点、颜色或线路
形状。

普通输入、输出以及 `VIA.IO` 都能同时连接多条线路。普通线路必须是输出到输入；输入不能
直接连接输入，输出也不能直接连接输出。`VIA.IO` 可连接输入、输出或另一个 VIA，但合并后
的整个网络仍只能有一个真实输出驱动源。相同端点对不能重复创建线路，所有端口的明确位宽
也必须一致；这些检查失败时不会留下半条线路或改变原网络。

前端用普通元件端口替换 VIA 时，应调用“将 VIA 合并到端口”积木。后端会在一次事务中把
所有 `VIA.IO` 线路改接到目标端口，保留原 `lineId`，删除 VIA 与目标端口之间形成的
零长度线路，再检查重复端点、方向、位宽和多驱动。全部合法才删除 VIA 并提交；任一检查
失败时，线路、VIA、绑定和运行状态都保持原样。不要在 Scratch 中用多次删除和创建积木
拼接这个操作。

结构和快照中的线路格式为 `{ "id": "wire-a", "from": "source.OUT", "to": "gate.A" }`。
导入时每条线路都必须包含唯一且非空的 `id`，元件类型也必须使用菜单中的规范英文名称。

## 常用端口

| 元件 | 输入端口 | 输出端口 |
| --- | --- | --- |
| LEVEL_INPUT | 无 | `OUT` |
| VIA | 无源 `IO`（自动位宽） | 无 |
| SWITCH | `A`, `S` | `OUT` |
| LEVEL_OUTPUT | `IN` | 无 |
| NOT | `A` | `OUT` |
| DELAY | `IN` | `OUT` |
| AND/OR/NAND/NOR/XOR/XNOR | `A`, `B` | `OUT` |
| 3 输入门 | `A`, `B`, `C` | `OUT` |
| 4 输入门 | `A`, `B`, `C`, `D` | `OUT` |
| HALF_ADDER | `A`, `B` | `SUM`, `CARRY` |
| FULL_ADDER | `A`, `B`, `CIN` | `SUM`, `COUT` |
| MUX | `A`, `B`, `SEL` | `OUT` |
| AOI / OAI | `A`, `B`, `C` | `OUT` |
| 4/8 比特加法器 | `A`, `B`, `CIN` | `SUM`, `COUT` |
| 1to8 / 1to2 分线器 | `IN` | `B0...B7` / `B0...B1` |
| 8to1 / 2to1 集线器 | `B0...B7` / `B0...B1` | `OUT` |
| 1to4 / 4to1 | `IN` / `B0...B3` | `B0...B3` / `OUT` |
| 2/4/8 分组转换器 | `IN0...` | `OUT0...` |
| REGISTER | `D`, `CLK` | `Q` |
| ROM | `ADDR` | `DATA` |
| RAM | `ADDR`, `DIN`, `WE`, `CLK` | `DOUT` |

AOI 实现 `NOT((A AND B) OR C)`，OAI 实现 `NOT((A OR B) AND C)`。
`SWITCH` 实现 `OUT = S ? A : 0`：`S=1` 时输出 `A`，`S=0` 时输出 `0`。
总线端口必须连接相同位宽的端口；VIA 会自动采用网络位宽。多输出端同时驱动同一网络会报告错误。

## 关卡数据示例

下面的数据验证一个连接在 `LEVEL_INPUT` 和 `LEVEL_OUTPUT` 之间的 NOT 门。示例中的
`Level_Input`、`Level_Output` 是元件 ID，不是类型名：

```json
输入列表: [{"Level_Input":0},{"Level_Input":1}]
期望列表: [{"Level_Output":1},{"Level_Output":0}]
```

每组对象必须包含所有 `LEVEL_INPUT` 和 `LEVEL_OUTPUT` 实例的组件 ID。它们注册时会自动加入
验证接口。结果示例：

```json
{"passed":true,"total":2,"passedCount":2,"failures":[]}
```
